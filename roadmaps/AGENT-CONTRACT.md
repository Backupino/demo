# قرارداد عاملها — Agent Contract

> **Status:** active · **Last updated:** 2026-11-04

## ۲) پروتکل تحویل «Handoff»

### الف) ترتیب خواندن اجباری پیش از شروع هر تسک
1. `roadmaps/README.md` «وضعیت فاز و پیشنیاز».
2. سند همان فاز «ردیف تسک، عامل، وضعیت، خروجی/معیار پذیرش، وابستگی».
3. `AGENT-CONTRACT.md` «این سند: دامنهٔ مجاز و RACI».
4. `docs/Dev/DECISIONS.md` «تصمیمات قفلشده».
5. `docs/Dev/DEVELOPMENT-RULES.md` «قانون صفر، بند ۱۷، نسخهگذاری `D-029`».

### ب) چرخهٔ هر تسک

```text
ورودی «سند/تصمیم/خروجی فاز قبل» ──► [AG-xxx: فقط دامنهٔ مجاز خود]
   ──► خروجی قابل بررسی + تست ──► AG-QA «صحتسنجی»
   ──► AG-DOCS «همگامسازی سند فاز و docs/Dev»
   ──► AG-ORCH «بهروزشانی وضعیت در README + ثبت D-xxx در صورت نیاز»
   ──► تحویل به ایجنت گیرندهٔ فاز بعد
```

### ج) قالب گزارش تحویل «هر ایجنت موظف است این بلوک را بسازد»

```text
TASK:    C2-T03
AGENT:   AG-ORCH
PHASE:   2
INPUT:   D-031, D-032, C2-T01
OUTPUT:  docs/Dev/... «مسیر دقیق», قرارداد Ed25519
CHECKS:  امضای دستکاریشده رد شد | fallback 7.4/8.4 مستند شد | لینکها سالم
STATUS:  done | blocked «دلیل» | needs-review
HANDOFF: AG-PRO «مصرفکنندهٔ کلید عمومی», AG-QA «تست امضا»
SCOPE:   فقط docs/Dev/ و roadmaps/ لمس شد | free/ دستنخورده
```

### د) قواعد رفتاری الزامی

| # | قاعده |
|---|---|
| 1 | هیچ ایجنتی **دامنهٔ انحصاری ایجنت دیگر** را تغییر نمیدهد؛ تداخل → گزارش به `AG-ORCH`، نه دور زدن |
| 2 | هیچ `git commit` / `push` / PR / merge / `git reset` / بازنویسی تاریخچه **بدون جملهٔ صریح مالک** مجاز نیست «قانون صفر» |
| 3 | اگر پیشنیاز فاز بسته نشده یا ورودی ناقص است: `STATUS: blocked` بدهد و حدس نزند / mock نسازد مگر اینکه سند فاز صریحاً mock را مجاز کرده باشد |
| 4 | هر تغییر در `free/` **ابتدا باید تسک فاز ۱ بگیرد** `D-045`؛ `P1-T12` نمونهٔ ثبتشده و اجرانشده است |
| 5 | ممنوعات سراسری: `eval`، CDN/فونت ریموت، تلهٔمتری بدون opt-in، هاردکد رنگ/فونت، دامنهٔ خام، `wp-config`، توکنها، IP پایدار، ربات مرکزی در `free/` |
| 6 | بعد از هر تسک: ردیف تسک «وضعیت + خروجی»، سند فاز، `docs/Dev/` و در نهایت `roadmaps/README.md` توسط `AG-ORCH` بهروز شوند |
| 7 | `AG-QA` حق **وتو** دارد: بدون تأیید آن هیچ تسکی `done` نمیشود، حتی اگر ایجنت اجراکننده گزارش `done` داده باشد |

## ۴) قالب استاندارد ردیف تسک «در تمام اسناد فازها»

```text
| ID | عامل | وضعیت | تسک | خروجی / معیار پذیرش | وابستگی |
```

| ستون | معنی برای ایجنت |
|---|---|
| `ID` | شناسهٔ یکتا؛ بدون آن تسک قابل ارجاع نیست |
| `عامل` | **یک** ایجنت مسئول `AG-xxx`؛ همکاری در جدول «تخصیص عاملها»ی همان فاز میآید، نه در این ستون |
| `وضعیت` | `⏳ todo` / `🔄 in-progress` / `✅ done` / `🛑 blocked`؛ فقط `AG-ORCH` آن را به `done` نهایی میکند |
| `تسک` | فعل امری + شیء مشخص «چه بسازد»، نه توضیح کلی |
| `خروجی / معیار پذیرش` | فایل/artifact یا شرط قابل اجرا که `AG-QA` بتواند امتحانش کند |
| `وابستگی` | `ID` تسک یا فاز پیشنیاز؛در غیر این صورت «—» |

3. دامنهٔ مجاز نشست حاضر: **فقط `docs/Dev/` و `roadmaps/`** `D-046`. سورس افزونه دستنخورده است.
