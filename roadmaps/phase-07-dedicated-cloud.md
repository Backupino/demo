## چرا جدا و بعد از لانچ؟

مالک صریحاً خواست ابر اختصاصی بعد از کاملشدن **افزونهٔ Pro + سایت + ربات** و بهعنوان ارتقای نسخههای بعدی اعمال شود. بنابراین `S3-T11` و `P4-T07` قدیم از فازهای ۳ و ۴ حذف شدند. در فاز ۲ فقط **فیلدهای قرارداد رزرو** میشوند تا فاز ۷ مجبور به migration نشود.

| رزرو در فاز ۲ «بدون پیادهسازی» | پیادهسازی در فاز ۷ |
|---|---|
| `plan.cloud_quota`، `cloud_versions`، `usage` در JSON لایسنس | باکت S3-سازگار داخلی + آپلود مستقیم امضاشده |
| شمای `backup_index` و `signed-upload-url` در API | کلاینت ابر اختصاصی در Pro + داشبورد مصرف در پنل |
| فلگ `zero_knowledge` / الگوریتم رمزنگاری | AES-256-GCM «یا XChaCha20-Poly1305» سمت مشتری |
| سیاست `۳ اخطار / ۶۰ روز / حذف` بهصورت داده | اخطار ۸۰٪، توقف آپلود جدید در ۱۰۰٪ «بکاپ محلی ادامه دارد»، حذف قدیمیترین همان دامنه |
| نسخهبندی `free 1.1.x / pro 1.1.x / portal 1.1.x` | تعرفهٔ حجم اضافه، SLA، DR، مانیتورینگ، تست نشت داده |

## معماری ریکاوری «`D-044`»

دیگر «کلید گم شد = داده از بین رفت» پذیرفته نیست؛ مدل **zero-knowledge قابل ریکاوری با کنترل مشتری**:

| لایه | طراحی |
|---|---|
| رمزگذاری | هر سایت یک `DEK` تصادفی؛ بکاپها **قبل از خروج از سرور مشتری** رمز میشوند؛ پنل فقط ciphertext میبیند |
| بستهبندی | `DEK` با `KEK` حاصل از passphrase مالک «`sodium_crypto_pwhash` / Argon2id» wrap میشود؛ فقط `wrapped_DEK` ذخیره میگردد |
| عبارت بازیابی | یکبار نمایش داده میشود و **هرگز روی سرور ذخیره نمیشود**؛ جبران فراموشی passphrase |
| **Shamir ۲از۳ برای همهٔ پلنها** | سهمی روی سایت، سهمی در پنل «قفل با ۲FA مالک»، سهمی نزد کاربر؛ **هیچ سرور واحدی بهتنهایی قابل بازسازی نیست**؛ شامل Trial و شخصی هم میشود |
| سازمانی اختیاری | escrow در HSM + تأیید دو نفره + تأخیر ۲۴ساعته + اعلان به مالک + لاگ حسابرسی |
| چرخش و انقضا | `DEK` نسخهبندیشده؛ تغییر passphrase = re-wrap؛ نسخههای قدیمی تا پایان نگهداری اسنپشاتها باقی میمانند؛ ریکاوری بعد از انقضای لایسنس تا **۶۰ روز** مجاز است `D-015` / `PRODUCT-PLANS.md §5` |
| امنیت عملیات | ۲FA اجباری، نرخمحدود، اعلان ریکاوری، لاگ فقط هششده، هیچ plaintext/passphrase/عبارت بازیابی در لاگ یا DB پنل |

> نتیجهٔ صریح: **داده قابل برگشت است، ولی ما بهتنهایی قادر به خواندن بکاپهای کاربر نیستیم.**
