# قرارداد مانیفست و بسته‌های دلتای بکاپ افزایشی (Incremental Backup) — Backupino

> **وضعیت سند:** ✅ نهایی و مصوب (Approved)  
> **شناسه تسک:** `C2-T15` · **فاز:** فاز ۲ (قرارداد مشترک «Gate»)  
> **عامل مسئول:** `AG-CORE` (معمار هسته و خط لوله بکاپ)  
> **تصمیمات مرتبط:** `D-017`، `D-020`، `D-046`، `D-048`، `D-050` در [`DECISIONS.md`](DECISIONS.md)  
> **پیشنیازها:** اسناد مصوب [`FREE-EXTENSION-HOOKS-CONTRACT.md`](FREE-EXTENSION-HOOKS-CONTRACT.md) و [`LOCAL-RESTORE-PIPELINE-CONTRACT.md`](LOCAL-RESTORE-PIPELINE-CONTRACT.md).  
> **دامنه:** طراحی ساختار داده‌ای شناسنامه مانیفست (`manifest.json`)، ژورنال حذفیات (`deletions.json`)، بسته‌های دلتا، منطق بازگردانی ماشین زمان (Time Machine Restore) و ادغام با درایورهای FTP و S3.

---

## ۱. اهداف و مزایای معماری بکاپ افزایشی

1. **کاهش ۹۰ درصدی مصرف منابع (`D-050`):** در وب‌سایت‌های حجیم وردپرسی (دارای گیگابایت‌ها تصویر در `uploads`)، اجرای روزانه بکاپ کامل موجب مصرف شدید CPU، درگیر شدن I/O دیسک و مصرف بیش‌ازحد پهنای باند شبکه می‌شود. با روش افزایشی، صرفاً فایل‌هایی که تغییر کرده یا جدید هستند بسته‌بندی می‌شوند.
2. **پشتیبانی کامل از هاست‌های دانلود ارزان و بومی (`D-048`):** سازگاری کامل با هاست‌های cPanel و DirectAdmin ایران از طریق درایورهای FTP/FTPS/SFTP و باکت‌های S3 محلی (مانند ابر آروان و پارس‌پک) بدون نیاز به ابزارهای پیچیده سروری.
3. **بازگردانی به هر نقطه زمانی (Time Machine Point-in-Time Restore):** امکان بازگردانی دقیق وب‌سایت به وضعیت هر روز مشخص از طریق ترکیب نسخه پایه کامل و بسته‌های دلتای متوالی.

---

## ۲. زنجیره بکاپ (Backup Chain Architecture)

هر چرخه بکاپ شامل یک زنجیره پیوسته است:

```
[Base Full Backup (Seq 0)] ──> [Delta Pack 1 (Seq 1)] ──> [Delta Pack 2 (Seq 2)] ──> [Delta Pack 3 (Seq 3)]
        │                               │                              │                             │
    manifest.json                   manifest.json                  manifest.json                 manifest.json
    (پایه‌ریزی اثرانگشت‌ها)         (فایل‌های ۲۴ ساعت گذشته)       (فایل‌های ۲۴ ساعت گذشته)      (نقطه زمانی ۳)
```

- **شناسه زنجیره (`chain_id`):** رشته تصادفی ۱۶ کاراکتری یکتا برای هر چرخه (مانند `chn_8f93a10c7b2e`).
- **شماره توالی (`sequence_number`):** عدد صحیح ترتیبی؛ `0` نشان‌دهنده نسخه پایه کامل (Full) و اعداد `1, 2, ...` نشان‌دهنده بسته‌های دلتا هستند.
- **تثبیت دوره‌ای (Synthetic Full):** پس از رسیدن توالی به عدد ۳۰ (یا بر اساس تنظیم کاربر)، زنجیره جدیدی با یک بکاپ کامل جدید شروع می‌شود.

## ۳. ساختار داده‌ای شناسنامه مانیفست (`manifest.json`)

فایل `manifest.json` درون هر پکیج بکاپ (کامل یا دلتا) ذخیره شده و ساختار استاندارد زیر را دارد:

```json
{
  "schema_version": "1.0.0",
  "chain_id": "chn_8f93a10c7b2e4d91",
  "sequence_number": 2,
  "backup_type": "incremental",
  "parent_manifest_sha256": "4a539e083c79c8ca6...e6a",
  "manifest_sha256": "9b12a88f6109e4a5...11c",
  "created_at": "2026-11-05T03:00:00Z",
  "site_info": {
    "url": "https://example.com",
    "table_prefix": "wp_",
    "free_version": "1.0.2",
    "pro_version": "1.0.0"
  },
  "stats": {
    "total_scanned_files": 14250,
    "delta_added_files": 12,
    "delta_modified_files": 5,
    "delta_deleted_files": 3,
    "delta_payload_bytes": 15420912
  },
  "files": [
    {
      "path": "wp-content/uploads/2026/11/banner.webp",
      "size": 245100,
      "mtime": 1730793600,
      "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
    },
    {
      "path": "wp-content/uploads/2026/11/report.pdf",
      "size": 15175812,
      "mtime": 1730794200,
      "sha256": "1a2b3c4d5e6f7a8b9c0d1e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2b"
    }
  ]
}
```

- **الگوریتم تشخیص تغییر فایل:**
  1. اگر مسیر در مانیفست قبلی وجود نداشت: **فایل جدید (Added)**.
  2. اگر `size` یا `mtime` تغییر کرده بود: محاسبه چانک‌شده هش `sha256`. در صورت تفاوت هش: **فایل ویرایش‌شده (Modified)**.
  3. در صورت یکسان بودن اندازه، زمان و هش: فایل دست‌نخورده باقی مانده و در بسته دلتا گنجانده نمی‌شود.

## ۴. ساختار ژورنال حذفیات (`deletions.json`)

برای تضمین بازگردانی دقیق بدون باقی ماندن فایل‌های یتیم یا حذف‌شده:

```json
{
  "chain_id": "chn_8f93a10c7b2e4d91",
  "sequence_number": 2,
  "deleted_at": "2026-11-05T03:00:00Z",
  "deleted_paths": [
    "wp-content/uploads/2026/10/old-temp-image.jpg",
    "wp-content/uploads/cache/tmp-cache-99.png",
    "wp-content/plugins/uninstalled-test-addon/addon.php"
  ]
}
```

## ۵. ساختار فیزیکی بسته دلتا (Delta Pack File Layout)

هر بسته دلتا در قالب یک آرشیو فشرده مستقل با پسوند استاندارد ذخیره می‌شود:

```
backupino-delta-chn_8f93a10c-seq002.bkp (یا .zip)
├── manifest.json              # شناسنامه تغییرات و مشخصات این توالی
├── deletions.json             # لیست فایل‌های حذف‌شده از نسخه قبلی
├── database.sql.gz            # دامپ کامل دیتابیس در این نقطه زمانی
└── payload/                   # محتوای باینری فایل‌های افزوده یا ویرایش‌شده
    └── wp-content/
        └── uploads/
            └── 2026/
                └── 11/
                    ├── banner.webp
                    └── report.pdf
```

> **نکته معماری دیتابیس در دلتا:** از آنجا که دیتابیس وردپرس متنی و بسیار فشرده‌پذیر است، در هر بسته دلتا یک دامپ کامل تازه از دیتابیس گنجانده می‌شود تا نیازی به لاگ‌های دودویی پیچیده (MySQL Binlog) نبوده و بازگردانی دیتابیس در هر مرحله مستقل و قطعی باشد.

## ۶. یکپارچگی با درایورهای ذخیره‌سازی مقصد (`D-048`)

### ۶.۱. هاست‌های دانلود (cPanel / DirectAdmin via FTP / FTPS / SFTP)
- فایل‌ها درون پوشه با ساختار مرتب ذخیره می‌شوند:
  ```
  /public_html/backups/
  └── example.com/
      └── chn_8f93a10c/
          ├── base-seq000.bkp
          ├── delta-seq001.bkp
          ├── delta-seq002.bkp
          └── chain-index.json
  ```
- **فایل `chain-index.json`:** خلاصه‌ای بسیار سبک از کل زنجیره برای نمایش سریع لیست نقاط زمانی در پیشخوان بدون نیاز به لیست کردن تمام پوشه‌ها با فرمان‌های کند FTP.

### ۶.۲. کلادهای سازگار با S3 (ArvanCloud, ParsPack, AWS S3, Cloudflare R2)
- ساختار مسیر باکت:
  `s3://{bucket-name}/{domain_hash}/{chain_id}/seq-{number}.bkp`
- ذخیره متادیتای `x-amz-meta-chain-id` و `x-amz-meta-seq` روی هر آبجکت جهت ایندکس‌گذاری و اعتبارسنجی سریع.

## ۷. فرآیند بازگردانی ماشین زمان (Time Machine Restore Pipeline)

هنگامی که کاربر در صفحه بازگردانی نقطه‌ای مانند «نسخه دلتا ۳» را انتخاب می‌کند:

```
[ دانلود یا لود بسته پایه Seq 0 ]
              │
              ▼
[ استخراج کامل فایل‌های پایه و دیتابیس به شاخه موقت ]
              │
              ▼
[ اعمال به ترتیب بسته دلتا Seq 1 ──> رونویسی فایل‌ها + اعمال deletions.json ]
              │
              ▼
[ اعمال به ترتیب بسته دلتا Seq 2 ──> رونویسی فایل‌ها + اعمال deletions.json ]
              │
              ▼
[ اعمال به ترتیب بسته دلتا Seq 3 ──> رونویسی فایل‌ها + اعمال deletions.json ]
              │
              ▼
[ ایمپورت دیتابیس نهایی موجود در Seq 3 ]
              │
              ▼
[ بازنویسی URLها و نهایی‌سازی ریستور ]
```

## ۸. سیاست‌های نگهداری و پاکسازی زنجیره (Retention Policy)

مطابق `D-017`:
1. **قانون وابستگی زنجیره (Chain Dependency Invariant):** یک پکیج پایه Full (`Seq 0`) به هیچ عنوان تا زمانی که حداقل یک بسته دلتا (`Seq > 0`) به آن وابسته است، حذف نخواهد شد.
2. **پاکسازی یکپارچه:** زمانی که عمر زنجیره یا سقف تعداد نسخه‌ها فرا برسد، کل زنجیره (`Seq 0` تا `Seq N`) به عنوان یک واحد یکپارچه حذف می‌گردد تا هیچ دلتای یتیم و غیرقابل‌بازگردانی باقی نماند.
