## ۱. نمای کلی اکوسیستم مخازن بکاپینو (The 5 Repositories)

| نام مخزن گیت‌هاب | نوع دسترسی | شاخه پیش‌فرض | مسیر محلی روی سیستم (Local Path) | شرح و وظیفه مخزن |
|---|---|---|---|---|
| **`Backupino/dev`** | 🔒 خصوصی (Private) | `Phase1` | `D:\Works\AniGravity\tools\Backupino\` | **هاب مرکزی مهندسی (Monorepo):** دربرگیرنده کل کدها، تست‌ها، ابزارهای ساخت، نقشه‌های راه و اسناد داخلی. |
| **`Backupino/plugin`** | 🌐 عمومی (Public) | `main` | `D:\Works\AniGravity\tools\Backupino\free\` | **سورس رسمی نسخه رایگان:** منحصراً کدهای افزونه رایگان جهت انتشار در WordPress.org بدون فایل اضافی. |

## ۲. کالبدشکافی وظایف و محتویات هر مخزن

### ۲.۱. مخزن اصلی و خصوصی توسعه (`Backupino/dev`)
- **ماهیت:** این مخزن تنها مخزن جامع پروژه است و به عنوان ریشه فضای کاری (Workspace Root) توسعه‌دهندگان و ایجنت‌ها عمل می‌کند.
- **محتویات:**
  - پوشه `free/`: سورس نسخه رایگان (متصل به مخزن `plugin`).
  - پوشه `pro/`: سورس نسخه حرفه‌ای (متصل به مخزن `pro`).
  - پوشه `docs/Public/`: کپی محلی مستندات کاربری (متصل به مخزن `documents`).
  - پوشه `docs/Dev/`: مستندات داخلی تیم فنی (قوانین، چک‌لیست‌ها، معماری).
  - پوشه `roadmaps/`: نقشه‌های راه، فازها، تسک‌ها و چک‌پوینت‌ها.
  - پوشه `tests/`: مجموعه کامل تست‌های خودکار واحد، یکپارچه‌سازی و رگرسیون.
  - پوشه `tools/` و `bin/`: ابزارهای کامپایل اینستالر، بیلد بسته‌ها و رانر PHP-WASM.
- **قانون طلایی:** این مخزن **کاملاً محرمانه** است. هیچ لینکی در مخازن عمومی (`plugin` و `documents`) یا سایت اصلی نباید به مخزن `dev` یا شاخه‌ها و PRهای آن اشاره کند.

---

### ۲.۲. مخزن عمومی سورس افزونه رایگان (`Backupino/plugin`)
- **ماهیت:** سورس تمیز نسخه رایگان افزونه که برای بررسی بازبین‌های مخزن وردپرس و جامعه متن‌باز باز است.
- **مسیر محلی:** پوشه `free/` درون فضای کاری `dev`.
- **محتویات مجاز:**
  - فایل اصلی `backupino.php` و `uninstall.php`
  - فایل `readme.txt` استاندارد وردپرس
  - پوشه `src/` (تمامی کلاس‌های مجاز رایگان با گارد `ABSPATH`)
  - پوشه‌های `templates/`، `assets/` و `languages/`
  - فایل `README.md` در ریشه مخزن (معرفی، نشان‌ها، لینک‌های سایت و مستندات)
- **ممنوعیت‌های اکید:**
  - هیچ فایل تستی (`tests/`)، هیچ ابزار بیلدی (`bin/`، `tools/`)، هیچ سندی از فازها یا رودمپ‌ها نباید وارد این مخزن شود.
  - هیچ کدی وابسته به لایسنس یا ویژگی‌های پولی نباید در این مخزن وجود داشته باشد.

---

### ۲.۳. مخزن عمومی مستندات سمت کاربر (`Backupino/documents`)
- **ماهیت:** دانشنامه عمومی و راهنمای کامل برای مدیران سایت‌ها و کاربران نهایی.
- **مسیر محلی:** پوشه `docs/Public/` درون فضای کاری `dev`.
- **محتویات مجاز:**
  - ساختار پارتیشن‌بندی‌شده در ۶ پوشه استاندارد (`01-getting-started` تا `06-faq`).
  - فایل جامع `README.md` در ریشه که نقشه اطلس مستندات را تشکیل می‌دهد.
- **ممنوعیت‌های اکید:**
  - هیچ سخنی از فازها، شماره تسک‌ها، روند توسعه، بازبین‌های داخلی یا برنامه‌های محرمانه تیم نباید در این مخزن نوشته شود.
  - هیچ پیوندی به مخازن خصوصی `dev` یا `pro` نباید وجود داشته باشد.

---

### ۲.۴. مخزن خصوصی نسخه حرفه‌ای (`Backupino/pro`)
- **ماهیت:** مخزن خصوصی برای توسعه ماژول‌های تجاری افزونه.
- **مسیر محلی:** پوشه `pro/` درون فضای کاری `dev`.
- **محتویات:**
  - درایورهای ذخیره‌سازی ابری پیشرفته (AWS S3، Google Drive، Cloud Storage اختصاصی).
  - سیستم رمزنگاری پیشرفته پکیج‌ها و سیستم اعتبارسنجی لایسنس.
  - فایل `autoload.php` و تست‌های اختصاصی درایورها.

## ۴. پروتکل و قوانین کامیت و پوش (Commit & Push Workflow Protocol)

هر زمان توسعه‌دهنده یا ایجنت هوش مصنوعی تغییری در پروژه ایجاد می‌کند، باید دقیقاً طبق قوانین زیر عمل کند تا همزمانی و سلامت مخازن تضمین شود:

### سناریوی ۱: تغییر در کدهای افزونه رایگان (`free/`)
1. **توسعه و تست:** کدها در پوشه `free/` ویرایش شده و تست‌های واحد با دستور `node tools/run-php.mjs tests/run.php` اجرا می‌شوند.
2. **کامیت در مخزن افزونه:**
   ```powershell
   git -C free add -A
   git -C free commit -m "feat/fix: توضیح تغییرات"
   git -C free push origin main
   ```
3. **کامیت در مخزن dev:**
   ```powershell
   git add free/
   git commit -m "feat/fix: همگام‌سازی سورس افزونه رایگان با آخرین تغییرات"
   git push origin Phase1
   ```

### سناریوی ۲: تغییر در مستندات سمت کاربر (`docs/Public/`)
1. **ویرایش:** اسناد مربوطه در پوشه `docs/Public/` با نگارش تمیز و بدون ادبیات توسعه ویرایش می‌شوند.
2. **کامیت در مخزن مستندات:**
   ```powershell
   git -C docs/Public add -A
   git -C docs/Public commit -m "docs: توضیح تغییرات مستندات"
   git -C docs/Public push origin main
   ```
3. **کامیت در مخزن dev:**
   ```powershell
   git add docs/Public/
   git commit -m "docs: به‌روزرسانی مستندات عمومی در مخزن توسعه"
   git push origin Phase1
   ```

### سناریوی ۳: تغییر در کدهای نسخه تجاری (`pro/`)
1. **توسعه و تست:** کدهای درایورها در `pro/src/` ویرایش و با تست‌های `tests/Pro/` اعتبارسنجی می‌شوند.
2. **کامیت در مخزن pro:**
   ```powershell
   git -C pro add -A
   git -C pro commit -m "feat(pro): توضیح قابلیت تجاری"
   git -C pro push origin main
   ```
3. **کامیت در مخزن dev:**
   ```powershell
   git add pro/
   git commit -m "feat(pro): همگام‌سازی نسخه تجاری در dev"
   git push origin Phase1
   ```

### سناریوی ۴: تغییر در تسک‌ها، تست‌ها یا مستندات فنی تیم (`tests/`, `docs/Dev/`, `roadmaps/`)
این بخش‌ها منحصراً متعلق به مخزن مرکزی هستند؛ بنابراین فقط در ریشه مخزن `dev` کامیت و پوش می‌شوند:
```powershell
git add tests/ docs/Dev/ roadmaps/
git commit -m "chore/docs: به‌روزرسانی رودمپ یا تست‌های داخلی"
git push origin Phase1
```

## ۵. چک‌لیست ایمنی پیش از هر Push برای ایجنت‌های هوش مصنوعی

پیش از ارسال دستور `git push` در هر یک از مخازن، ایجنت هوش مصنوعی باید موارد زیر را کنترل کند:
- [ ] تست‌های PHP (`npm test`) ۱۰۰٪ سبز هستند و هیچ تستی شکسته نشده است.
- [ ] در مخزن `plugin` هیچ فایلی از `tests/`، `bin/` یا پوشه‌های توسعه‌ای وجود ندارد.
- [ ] در مخزن `documents` هیچ واژه‌ای از فازها، تسک‌ها، اسرار تیم یا لینک‌های داخلی مخزن dev دیده نمی‌شود.
- [ ] گارد امنیتی `defined( 'ABSPATH' ) || exit;` در فایل‌های PHP لایه `free/` حفظ شده است.
- [ ] نام برند در متن‌های فارسی کاملاً یکپارچه و به صورت **بکاپینو** نوشته شده است.
- [ ] تأیید کاربر برای کامیت و پوش دریافت شده است (قانون صفر).
